# 013-blueprint-voice-interface-v1：语音输入接口开发参照

本文把 007 至 011 的推导收成一份开发参照，供调用方按记录实现适配器。文中的划分、记录、迁移与配对都是候选，不是已确认的设计。对抗审查的五条异议，凡是用原语里没有的闸门、调用形状或另一套产品换掉原语的，本参照不采用；凡是仍然缺观察的，改记到 012，这里不补猜测。

用户要求的是一个可接入的语音输入接口，并用其点名的豆包输入法离线本地模型与云端大模型接口优化语音输入。接口通用，指的是离线模型与云端接口坐在适配器（adapter）背后，调用方看见的类型不随某一家字段改变。点名只说明绑定（binding）的候选制品是哪一组。

下文原语均指 `dev-docs/notes/007-derivation-voice-input-primitives.md`。008 至 012 均指 `dev-docs/notes/` 下同号笔记。

## 架构

### 一次会话上的九条原语

语音优化输入不是「采样进入、提交文本（commit）出来」的一个总函数。007 §1 把它拆成四件先后不同的事：采样帧还不是字；识别假设可以被更晚的假设修订，所以还不是宿主文档上的提交；在上下文上决定保留还是换成另一段文本，这是优化，不是再听一遍麦克风；文本进入宿主字段时，预编辑文本（preedit）可被替换，提交文本进入宿主文档。二者都不是识别流（recognition stream）本身。

007 §2.3 与 §3 把可以独立替换的维度收成九条原语。替换其中一维时，其余各条的输入类型、输出类型与不变量仍然成立。一次语音优化输入是这九条在同一个会话（session）上的组合。007 §4 不给这次组合另起总函数，也不另起命名预设。本参照沿用这道取舍：架构上没有第十个「语音优化」对象把九条焊回去。

候选的数据依赖如下。它是组合顺序，不是一个函数的步骤表。

1. 触发（trigger）只发出打开或关闭。输出里没有采样帧，也没有文本。
2. 会话在打开成功时记下标识、宿主字段标识的快照、范围快照，以及「允许交付 / 拒绝交付」。
3. 上下文（context）在打开时只读汇集一份槽位快照（context snapshot）。汇集不写宿主字段，不写键盘组合（keyboard composition），不写模型权重。
4. 绑定按角色装上适配器。契约尚未可调用时，该角色空着，其余类型不改。
5. 采集（capture）交出带显式格式的有序采样帧，或「无帧并结束」。帧上没有文本。
6. 识别流吃帧、快照与会话标识，交出假设。假设的替换留在会话内。
7. 改写流（rewrite stream）吃一条已经是文本的假设、快照与会话标识，交出「不替换」或「替换为这段文本」。它不吃采样帧，不持有宿主字段。
8. 呈现（presentation）把假设与改写结果排成变更意图。它不写字段。
9. 交付（delivery）对一条意图整笔应用，或整笔拒绝。拒绝时字段与应用前逐字相同。

采集不读取改写结果。识别流不选择交付通道。改写流不读取键盘组合。呈现不发明改写文本。交付的输入里没有采样帧，也没有制品身份。这些边界来自 007 §3 各条不变量，不是本参照新加的总控。

### 三份记录，不是一个语音态

008 §1.1 把「字什么时候算进宿主字段」收成三份记录，而不是一个叫「语音态」的对象：会话回答还许不许写；事务回答这一条意图是整笔写上还是整笔不动；共存约束回答未被取走的键盘事件如何进入既有键盘链。三者用同一枚会话标识互相引用，不共享键盘组合的状态。

本参照保留这三份记录的分法，并改掉其中两处被异议点名的焊法，详见关键实现决定：

- 共存约束不再包含「自有预编辑区间还在时，未取走的事件停在键盘链之外」。原语 2 的不变量是：未被取走的事件原样进入键盘组合，触发不读键盘组合状态。
- 会话状态机不再包含「同一字段至多一枚允许交付」，也不包含「同一会话提交至多成功一笔，且这笔是最后一笔交付」。

008 §1.2 已经舍弃、本参照继续不采用的状态机有：录音中 / 润色中 / 上屏完成三段式；触发的关闭信号立刻等于会话关闭；失焦即销毁会话并清掉假设；用键盘引擎的会话标识充当语音会话标识；每条部分假设一笔提交再覆盖；把语音字符串编码成按键交给键盘组合；在键盘路径内部增加语音分支；关闭之后补一次清预编辑的写入。这些舍弃分别对应 007 的焊法 C、E、F、G 与原语 1、原语 2。

### 两条路径只在宿主字段相遇

键盘事件仍走键盘输入路径，产生键盘自己的组合与提交。语音路径不把采样帧、识别假设、改写结果或变更意图交给那条路径，也不从那条路径读出语音进行到哪一步。007 §1 与原语 8：两条路径只在宿主字段相遇，都能读光标周围的文本，都能写预编辑或提交。

触发对一枚键盘事件只有两个结果。取走：该事件不进入键盘组合，只用于产生打开或关闭，取走本身不写字段。不取走：事件的类型与修饰保持原样，进入键盘链。进入之后，键盘链上的函数不因语音而出现第二套分支。008 §6.2 对现行 Squirrel 的距离是：`handle` 把按下与修饰键变化译成键盘码，调用 `process_key`，再进入键盘更新；这条链上没有语音会话判断。该事实说明键盘路径尚未被改写，不是一道已经存在的闸门，也不被本参照收成「在链内插入判断」。

自有预编辑已经显示时，未取走的事件仍然进入键盘链。此后字段上的预编辑与提交各变成什么，012 §1 记为未知。语音交付若无法把意图中的范围对应到自己有权替换的那一段，就整笔拒绝，而不是把事件拦在链外。008 §6.2 还写明：现行失焦处置提交的是键盘原始编码；空字符串的插入对一段不是键盘路径放上去的预编辑做什么，现行源码没有说明。语音会话不把那段既有处置订阅成自己的提交。

### 绑定坐在适配器后面

原语 9：绑定变化的是哪一件制品担任识别流、哪一件担任改写流。制品的所在地不是角色。用户点名的两件制品是豆包输入法所带的离线模型，以及豆包输入法的云端大模型接口。点名不说明角色配对。007 焊法 B 舍弃「离线制品 = 识别流，云端制品 = 改写流」。

适配器对外满足原语 4 或原语 5 的输入输出，对内接某一件制品。契约未知时适配器不成立，角色空着，不因此改写其余原语的类型。打开模型容器与远程鉴权若只存在于官方进程内部，绑定的输出就是「该制品尚无可调用契约」，而不是一条绕过路径。本参照不写容器内部材料，不写从官方进程取出鉴权材料、复刻请求签名或把调用方进程换成官方输入法进程的做法。

009 观察到的进程内顺序（路径、槽位、部分文本与定稿文本）说明官方工人与宿主写入是分开的日志，不能当成进程外的调用入口。010 把点名云端制品拆成调用方自己的公开流式识别与公开对话，并把输入法进程里的长连接与整理路由划出绑定目标；011 仍把云端优化投影写到那条整理路由上。012 §4 写明这两篇没有交出同一份绑定。本参照的云端端口因此不是那两套公开产品，也不是那条整理路由的字段表。

### 架构边界

下表只标候选架构上「谁碰得到谁」。它不是类图。

| 记录或端口 | 读 | 写 | 碰不到 |
| --- | --- | --- | --- |
| 会话 | 打开时的字段标识与范围；此后挂在该标识上的假设与改写结果 | 寿命、交付许可、收束标记、自有区间登记、假设链 | 键盘组合状态；另一枚会话的范围 |
| 触发 | 键盘事件子集、采集的静音一类信号、识别流的分句定稿信号、失焦信号；均可缺席 | 某一会话的打开或关闭 | 采样帧、文本、宿主字段 |
| 采集 | 设备选择、使用权、会话开闭、设备侧格式变化 | 带格式的帧，或无帧并结束 | 识别假设、宿主字段 |
| 识别流 | 有序帧、快照、会话标识 | 假设序列 | 麦克风设备、宿主写入句柄、键盘组合 |
| 改写流 | 一条假设的文本、快照、会话标识 | 不替换，或替换文本；两者都保留原假设 | 采样帧、宿主字段、更新来源的指令 |
| 上下文 | 来源在该时刻的只读值 | 一份槽位快照 | 模型权重、提示词模板、宿主字段 |
| 呈现 | 假设、改写结果、会话开闭 | 变更意图 | 采样帧、制品身份、键盘事件 |
| 交付 | 一条意图、交付许可、宿主当前是否接受写入 | 预编辑或提交的相应变更，或拒绝 | 采样帧、键盘组合、另一条通道的私有参数 |
| 绑定 | 角色、制品、该制品声称能接受的输入类型 | 满足原语 4 或原语 5 的适配器实例，或角色空着 | 其余八条的类型定义 |

## 模块

### 候选包布局

007 §4 的反论写明：九条原语看起来像九个模块，但原语禁止的是输入输出类型互相牵连，不禁止同一次进程内顺序调用。本参照仍给出包布局，只为调用方能指出类型放在哪。目录边界不是进程边界，也不是九个目录各自独立运行的指令。不另设总控包：总控包会把 §架构 的数据依赖收成 007 已舍弃的焊法 A。顺序留在组合处，组合处不是第十个模块。

```text
voice-interface/
  session/          会话记录、寿命、交付许可、假设链
  trigger/          开闭信号
  capture/          带格式的采样帧
  recognition/      识别流端口
  rewrite/          改写流端口
  context/          槽位快照的只读汇集
  presentation/     变更意图
  delivery/         一条意图的事务
  binding/          按角色装上的适配器实例
```

`recognition/` 与 `rewrite/` 只放端口类型。豆包离线模型与豆包云端接口不是两个额外的公开类型系统，而是 `binding/` 里的两枚实例槽。契约可调用之前，这两枚槽的值是「角色空着」。实例槽不导出官方进程内部的类名、槽名或路由作为调用方类型。

各包公开的类型停在对应原语的输入输出上：

| 包 | 守的原语 | 公开类型停在 | 不放入该包的状态 |
| --- | --- | --- | --- |
| session | 原语 1 | 会话记录与迁移 | 采样帧、键盘组合 |
| trigger | 原语 2 | 打开或关闭 | 文本、帧 |
| capture | 原语 3 | 帧或结束 | 假设 |
| recognition | 原语 4 | 假设序列 | 宿主写入句柄 |
| rewrite | 原语 5 | 不替换或替换文本 | 帧、字段 |
| context | 原语 6 | 快照 | 提示词模板、权重 |
| presentation | 原语 7 | 意图 | 通道调用 |
| delivery | 原语 8 | 应用或拒绝 | 识别假设的产生 |
| binding | 原语 9 | 适配器实例或空角色 | 对其余八条类型的改写 |

### 四词测量

测量对象是上一节这九个包。测量不是改结构的指令。

清晰：目录名与原语一一对应，读的人能按原语编号找到类型，也能看出点名制品不在端口包里。代价是同一次调用栈会穿过多个目录，目录边界不等于调用边界；「字何时上屏」要同时看 presentation 与 delivery，不在单一目录里结束。

内聚：每个包的公开类型停在该原语的输入输出，delivery 的公开类型里没有采样帧，recognition 的公开类型里没有宿主写入句柄。代价是会话标识被多个包引用。标识的定义放在 session，其他包只引用这一枚类型，不把寿命、交付许可搬进那些包。

组合：替换 recognition 或 rewrite 的适配器，不改 presentation 与 delivery 的类型；binding 只产出满足端口的实例，或把角色留空。代价是一次会话上的先后顺序不在任何一个包内部。007 §2.1 允许同一进程、同一次调用栈顺序履行多条原语，顺序留在组合处。

优雅：没有总函数，没有「录音中 / 润色中 / 上屏完成」枚举，也没有在键盘链内增加语音分支。代价是组合处要同时看见九个端口，只打开一个包看不到整次输入；这是 007 §4 拒绝把清单再包装成前后端的同一代价。

## 接口

本节的记录是候选契约。调用方按这些记录实现适配器，并用原语 9 的核对句用替身逐条对照。记录不是宿主的函数表，也不是某一家请求的字段表。位置的平台单位、字段标识的平台值，未知处保持未知。

### 语音会话状态

会话标识与键盘引擎的会话标识不是同一枚。008 §6.1：现行树有 `RimeSessionId`，没有语音会话标识，没有打开时的字段快照，没有交付许可，也没有「收束已请求」与「已关闭」的分位。那些键盘标识留在键盘路径里。

打开成功时写入的候选记录：

| 字段 | 候选含义 |
| --- | --- |
| 会话标识 | 不透明。此后假设、改写结果、意图都携带它 |
| 字段快照 | 打开时记下的、可与「当前要写的那一份」比较的宿主字段标识。平台值未知，见 008 §5.1。比较失败则拒绝交付，不把快照改写成新字段 |
| 范围快照 | 打开时的范围。可以是空选区，表示光标插入点。位置的平台单位未知 |
| 寿命 | 未建立、开放、已关闭。已关闭之后，这枚标识不再接受任何交付。关闭不回滚已经写进文档的提交文本 |
| 收束已请求 | 是或否。已请求只说明触发不再把这次当作未收束。交付许可不因这一位单独关掉 |
| 交付许可 | 允许或拒绝。拒绝来自：会话标识不一致、寿命已关闭、字段标识偏离打开时的快照、宿主当前不接受写入。假设可以继续留在会话里 |
| 自有预编辑区间 | 无，或会话自己登记的一段范围。能否从宿主读回当前预编辑范围，未知，见 008 §5.5。读不回时，事务只依赖这份登记 |
| 假设链 | 有序。每条假设含假设标识、文本、修订目标（无，或某一条先前假设的标识）。空链不是错误 |
| 改写结果 | 未到；或「不替换」；或「替换为这段文本」。后两者都保留被改写的那条假设原文 |

不设「已应用提交」这一位。008 §3.1 用该位支撑「提交至多成功一笔」。该检查被异议 008#transaction 点名，012 §2 写明它不成为不变量。应用过的意图可以留在会话里供对照，对照本身不是拒绝理由。

未列出的输入不迁移。

| 当前 | 输入 | 迁到 | 字段 |
| --- | --- | --- | --- |
| 未建立 | 触发给出打开，且当时能记下字段标识与范围快照 | 开放，允许交付，收束未请求 | 不动 |
| 未建立 | 打开时字段标识记不下来 | 保持未建立 | 不动 |
| 开放，允许交付 | 触发给出关闭 | 仍开放，允许交付，收束已请求 | 不动。关闭信号本身不写字段 |
| 开放，允许交付 | 字段标识偏离快照 | 仍开放，拒绝交付 | 不动。不改写新字段，也不再改写旧字段。已提交文本保持。已经显示的预编辑区间不在这一迁移里被清除 |
| 开放 | 失焦信号，且触发不把它当成关闭，字段标识也未偏离快照 | 不迁移 | 不动。失焦不是标识 |
| 开放 | 失焦信号，且触发把它当成关闭 | 与「触发给出关闭」相同 | 不动 |
| 开放，允许交付 | 预编辑事务成功 | 寿命与许可不变；自有区间更新 | 只有自有区间被替换 |
| 开放，允许交付 | 提交事务成功 | 寿命保持开放，许可不变；自有区间变为无 | 该范围成为提交文本，不再处于预编辑。不因这一笔进入已关闭 |
| 开放，拒绝交付 | 任意识别假设或改写结果 | 寿命可保持开放 | 不动。结果留在会话记录里 |
| 开放，收束已请求 | 呈现不再持有未发出的意图，且自有区间为无 | 已关闭 | 不动 |
| 已关闭 | 任何迟到的假设、改写或意图 | 保持已关闭 | 不动 |

标识不一致的结果不进入上表，当前会话的各位不变，字段不动。

同一字段上第二枚会话请求打开时：原语 1 只禁止它们写进彼此的范围，并不禁止两枚同时允许交付。本参照不采用 008 §3.4 的「新打开不获得允许交付」。两枚会话的范围若在宿主上无法区分，交付按下一节「范围无法对应则拒绝」处理，这是逐条意图的拒绝，不是打开时的基数锁。宿主能否同时持有两段互不覆盖的预编辑，仍是 008 §5.10 的未知；012 没有把这一条另开成缺口。

不另给时钟。改写结果一直不到达、呈现仍持有待发意图时，哪一个会话以外的事实能让寿命进入已关闭，008 §5.7 记为未知。一段失焦、权限提示或状态栏交互是否等于字段标识偏离快照，008 §5.2 记为未知。状态机里失焦与字段偏离保持两行。

核对，回答是或否即可：任取一条结果，会话标识不一致，或寿命已关闭，或交付许可为拒绝时，预编辑文本与提交文本是否都保持不动？触发已经发出关闭、但呈现尚未发出意图时，字段是否尚未因此多出一段提交文本？

### 预编辑与提交

呈现输出的一条意图只含四字段：会话标识、范围、字符串、种类（预编辑或提交）。意图上没有采样帧，没有制品身份，没有键盘事件，没有更新上下文来源的指令。

范围的候选含义沿用 008 §3.2，交付不重新解释范围：

- 种类为预编辑，且会话尚无自有区间：范围等于打开时的范围快照。应用之后，会话把字段上刚写下的那段记为自有区间。
- 种类为预编辑，且已有自有区间：范围等于该自有区间。应用的可观察结果是自有区间的文本变成这条字符串，提交文本不增加。
- 种类为提交，且已有自有区间：范围等于该自有区间。应用的可观察结果是这段位置上的字成为提交文本，自有区间登记变为无。字段上不留下「仍带预编辑标记的草稿，再加上一段提交」两份副本。
- 种类为提交，且无自有区间：范围等于打开时的范围快照。

一笔事务处理一条意图。检查按下面的顺序。任一项失败：不调用宿主写入，自有区间登记也不前进。

1. 意图的会话标识等于这一份记录的标识。
2. 寿命是开放，不是已关闭。
3. 交付许可是允许。
4. 当前字段标识等于打开时的快照。
5. 宿主当前接受写入。
6. 种类为预编辑时：这条意图呈现的假设，是假设链上尚未被更晚已呈现假设盖过的那一条。它修订的若是更早的假设，而更晚的修订已经呈现过，则拒绝。识别流里的旧文本仍保留，只是不再写字段。
7. 种类为提交时：字符串来自呈现。允许的字符串只是会话里已有的假设原文，或改写结果已经给出的替换文本；改写结果为「不替换」时，字符串是假设原文。交付不调用改写流，也不在改写结果仍为「未到」时自己造一段优化文本。改写未到时，呈现仍可以发出使用假设原文的提交意图；这不是交付在造优化文本。

008 §3.3 的第 6 项「已应用提交为否，同一会话的提交意图至多成功一笔」不在上表。应用提交之后「这笔是该会话最后一笔成功的交付」也不在迁移表。012 §2：尚未观察到宿主事实时，事务检查不把「至多一笔成功提交」收成不变量。

应用预编辑：自有区间的可观察文本变为意图字符串；文档中已有的提交文本不变。

应用提交：该范围的可观察文本变为意图字符串，并且不再处于预编辑；自有区间变为无。会话保持开放，除非上一节的关闭行已经满足。同一会话里更晚的另一条提交意图，不因为已经应用过提交而在检查第 1 至第 5 项之外被拒绝。

通道的候选形状是：宿主文本客户端对预编辑的直接写入，或对提交的直接写入。意图的四字段不因通道增加。宿主拒绝时是否存在另一条通道，007 原语 8 不给定做法，本参照也不给定。008 §6.2：现行 `show` / `commit` 经过控制器上那份键盘预编辑缓存；语音意图若复用这两个函数，会改写这份缓存。这是距离，不是本参照的通道。按公共前缀只重绘预编辑后缀，不是原语 7 的不变量；事务的可观察结果是整段自有区间等于意图字符串。

呈现的两种意图序列都满足原语 7，本参照都保留为候选，不把其中一种写进事务检查。

候选序列甲，来自 007 §4 与 008 §4：部分假设只产生预编辑意图；改写结果未到时不发出提交意图，预编辑上可见的仍是识别假设自己的文本；收束已请求之后，改写结果为「不替换」则至多一笔提交、字符串是假设原文，为替换文本则这一笔使用替换文本。收束已请求而改写未到时，呈现仍持有待发的提交，寿命保持开放。

候选序列乙，来自 007 缺口 4：呈现可以先发出使用假设原文的提交意图，改写结果到达后再发出另一条字符串不同的提交意图，由后者替换。改写结果为「不替换」时，这一序列不再为优化另写一笔。008 §4 反论一允许的「收束时先提交假设原文，改写结果到达后不再写」只是序列乙的一个截断，不是原语 7 允许的全部。

目标宿主在收束之后、下一次写入之前是否仍留着预编辑，以及对同一范围连续两次提交且第二次字符串不同时文档历史上留下几段，012 §2 记为未知。在那两项观察出现之前，事务不替呈现选择序列甲或序列乙。

核对：在交付被完全断开的情况下，呈现是否仍能列出意图序列，且识别假设的原文仍可读取？连续三条部分假设是否可以只对应预编辑意图？若呈现改发序列乙，第二笔提交是否不会仅因「已经成功过一笔」而被事务拒绝？

### 上下文记忆的数据结构

原语 6 的输出是槽位快照：名字到文本的映射，不是某一个模型的提示词格式。同一份快照可以同时交给识别流与改写流。来源读不到时，对应槽位缺席，快照仍然成立。缺席用「没有这个槽」表示，不用空字符串顶替。空字符串会让投影分不清「宿主给了空文本」和「没有读到」。

011 §1.2 把一个槽的值放宽成一段文本，或有序的若干段文本。顺序属于快照。分隔符不进快照：样本只露出分隔配置键，字符未见，拼接若发生，发生在某个适配器自己的投影里，不发生在端口上。

一次汇集的候选快照：

| 槽位 | 值 | 缺席 |
| --- | --- | --- |
| `host_app` | 一段文本：宿主应用标识 | 给不出标识 |
| `field_role` | 一段文本：输入框角色 | 读不到角色 |
| `cursor_before` | 一段文本：汇集瞬间、光标之前、已经在字段里的文本。不含本会话的预编辑 | 宿主不提供周围文本 |
| `hotwords` | 有序的词文本。顺序是这次汇集看到的顺序 | 来源没有词 |
| `corrections` | 有序对。每对是两段文本，`src_text` 与 `dst_text`，表示曾经把 src 改成 dst | 来源没有对 |

`corrections` 进入快照之前，候选要求列表已经是消解之后的形状：同一个 `src_text` 至多一条 `dst_text`；不同时包含一对和它的反向对；传递链上不保留较旧的一跳。计数、时间戳、库内密文不进入槽位。来源如何挑选、如何消解，011 §1.3 与 §1.4 写明不是这次请求的形状；样本默认上限也不是快照的类型约束。本参照不另写一套写入或回写。

`host_app` 保存标识文本，不保存「这个应用应该用什么口吻」的生成句。识别假设、会话标识、采样帧都不写入槽位。假设与会话标识在改写请求上是原语 5 与原语 1 的输入，贴在改写端口的输入记录上，不进快照。

状态的候选迁移：

1. 未汇集。会话尚未打开，或一次读还没做完。两个流都还没有快照。没有「半份热词、半份前文」。
2. 已汇集。各次读取都有了结果，结果是值或明确缺席。快照在本会话内固定。识别流与改写流只读这一份。
3. 投影。某个适配器若持有可调用契约，可以把快照写成该契约自己的字段。投影不写回快照，不写回来源。契约不成立时，这一步没有可核对的写入。
4. 会话结束。这一份快照可以丢弃。来源不因会话结束而被改写。

汇集时刻的候选是会话打开时读一次。若另做一次只读读取，那是另一份快照，仍然满足原语 6，但光标前文可能被本会话的预编辑污染。011 §5.7：样本在两处使用的上下文是不是同一份字节，未测量。本参照的候选是打开时一份，不在预编辑写入之后把预编辑读回 `cursor_before`。

原语 1 的范围快照与 `cursor_before` 同时刻读取，但是不同的值。范围用于交付判定；前文文本用于优化。打开瞬间的范围不进入快照。

个人词、纠错对与键盘路径上已有的用户词是不是同一存储，007 缺口 5 与 011 §5.9 记为未知。快照不规定存储。输入框角色在目标宿主上从哪一个只读接口得到，011 §5.8 记为未知；读不到则 `field_role` 缺席。现行控制器能读到宿主应用标识，但标识停在键盘会话的选项上，没有进入这份快照；光标前文没有被读取（011 §6）。这是距离。读取用哪一个宿主调用，本参照不写成通道。

四槽全缺席时快照仍成立。核对：清空全部来源之后，识别流与改写流是否仍能按各自的输入类型运行？把同一份非空快照同时送进两个不同的流实现时，是否不需要为每个实现各写一份来源？

### 本地模型适配器的输入输出

本地模型适配器的对外类型就是识别流端口，或在可调用契约证明它只接受文本时改为改写流端口。007 原语 9：一件制品可以因它实际接受的输入类型而只担任其中一个角色。角色不按「在本机」预先焊死。

识别流输入是一条记录：

| 字段 | 候选含义 |
| --- | --- |
| 会话标识 | 原语 1 发出的那一枚 |
| 帧 | 有序。每一帧含字节，以及写在帧上的格式。格式至少能表达编码名称、采样率、声道数、是否交错。数值不由「当前加载了哪个模型」隐含。本端口不把 16 kHz、16-bit、单声道收成不变量 |
| 快照 | 上一节的快照。全部槽位缺席时仍然是合法输入 |

识别流输出是同一会话上的假设序列。每条假设是一条记录：

| 字段 | 候选含义 |
| --- | --- |
| 会话标识 | 与输入相同。标识不同的结果不写进彼此的范围 |
| 假设标识 | 本会话内可被后来的假设引用 |
| 修订目标 | 无，或本会话内某一条先前假设的标识。这是原语 4 的「标明它修订的是哪一条」 |
| 文本 | 假设正文。可以是空文本 |
| 分句已定稿 | 是或否。供触发消费。它不是提交文本，也不是预编辑文本 |

输出不含宿主写入句柄，不含制品身份，不含「去更新上下文来源」的指令。更晚的假设替换更早假设的文本时，替换发生在会话内，不自动变成宿主写入。

改写流输入与输出见下一节。若这件制品的可调用契约只满足其中一条，另一条角色不由它填。

豆包输入法离线模型这一枚绑定的现状：009 §1.1 与 §4 写明，执行进程内顺序的代码留在官方进程内，当前样本没有进程外导出。012 §3：没有不依赖容器内部材料的可调用入口时，这件制品的角色空着。009 §4 的三送一收——布局路径、两层内部槽名、16-bit PCM 块，收回物只有文本加「部分或定稿」——不是本端口。那份收回物没有会话标识，也没有修订目标。异议 009#adapter 因此不采用那三送一收作为调用方契约。

下列名字只作为「已经核对过、但不进入端口」的观察留下来，避免再被当成适配器的参数：主模型相对路径与上下文辅助目录、`BuildContextInfo` 与 `PromptProcessor` 的内部槽、`is_offline_result` 一类结果键。帧上的采样率与声道数，009 §3.4 没有在离线送音路径上核对成常量；端口只要求格式显式。没有观察到脱离送音的纯文本入口，不能单独证明这件制品不能担任改写流，只是仍然没有原语 5 的可调用契约（012 §3）。角色空着时，不打开容器来补入口。

调用方要开始写的是满足上表的适配器类型。点名离线制品的实例现在返回空角色。其余原语的核对使用不读取真实权重的识别替身：替身按上表接受帧、快照与会话标识，交回带修订目标的假设，不写预编辑。这是原语 9 的核对句，不是另一件制品。

核对：只喂帧、不提供任何宿主字段时，该适配器是否仍产出假设且不写预编辑？对同一会话连续给出两条互相修订的假设时，输出里是否能读出第二条的修订目标，并且没有任何一次提交文本因此发生？

### 云端优化适配器的输入输出

云端适配器的对外类型同样只是原语 4 或原语 5，由该制品可调用契约实际接受的输入决定，不由「在远程」决定。用户点名的制品是豆包输入法的云端大模型接口。007 缺口 3：样本的远程通道上既出现过识别假设，也出现过对定稿文本的改写；点名接口是否两样都提供，未知。因此这一枚绑定不预先配对成「只做改写」或「只做识别」。

改写流输入是一条记录：

| 字段 | 候选含义 |
| --- | --- |
| 会话标识 | 原语 1 的标识 |
| 假设标识 | 被改写的那一条 |
| 假设文本 | 已经是文本。通常来自分句已定稿的那条，类型上不要求带采样帧 |
| 快照 | 与识别流相同的那一份。槽位缺席则缺席，不换成空错误 |

改写流输出是一条记录：

| 字段 | 候选含义 |
| --- | --- |
| 会话标识 | 与输入相同 |
| 假设标识 | 与输入相同 |
| 原假设文本 | 输入中的假设文本，原样保留 |
| 种类 | 不替换，或替换 |
| 替换文本 | 仅当种类为替换时存在 |

「不替换」是正常输出，不是失败。此时呈现看到的文本仍是原假设。输出不含宿主字段，不含预编辑或提交的种类，不含更新来源的指令。空替换文本是否算「不替换」，没有协议字段可核对，010 §5 第 4 点记为未知；本端口不把空文本写成错误类型。

识别流一侧若将来的可调用契约接受有序帧并给出带修订目标的假设，同一套识别流记录也适用于这件制品。在读到那份契约之前，不把音频包字段写进改写输入，也不把改写输出写成识别假设。

豆包输入法云端大模型接口这一枚绑定的现状：012 §4 写明，官方进程之外的请求形状未知；它接受采样帧、定稿文本，还是两者都接受，未知；调用方自己持有的凭证能否使这份契约成立，未知。角色空着。010 写「用户点名的云端制品在这里拆成两面」，两面是公开流式识别与公开对话，并把输入法进程里的长连接与整理路由划出绑定目标。异议 010#binding 不采用这个替换。011 §3.4 把云端优化投影写到整理路由上，并写明那里的键名未知、逻辑字段不是观察到的报文。那份投影与 010 的两套公开接口不是同一份契约，本参照不把其中任何一份升成端口。两篇没有交出同一份绑定，这一矛盾改记在 012 §4，不在这里选一边当成点名制品。

私有长连接上的决策字段、整理对象上的校验标记，留在官方进程内部。本参照不记录令牌取值，不把调用方的另一套公开凭证写成那些私有主机的替代，也不写装成官方输入法进程的调用。公开接口盖不住的能力保持为缺口，不因此改写改写流记录的五个字段。

上下文进入云端适配器的方式只有一个：输入记录上的那份快照。适配器内部若要把槽位装填成某个契约的字段，装填代码不属于原语 6 的输出类型。契约未知时，没有可核对的装填。011 §3.3 的内部槽名与 011 §3.4 的逻辑请求草稿，都是投影备忘，不是调用方要实现的报文。

调用方要开始写的是满足改写流记录、或在契约证明吃帧时满足识别流记录的适配器类型。点名云端制品的实例现在返回空角色。核对用的恒等改写始终交出「不替换」，并在输出中保留原假设文本，不调用远程接口。换掉恒等实现时，识别流的帧输入与假设输出不改。

核对：对同一条假设把改写实现换成恒等之后，识别流与采集是否无需改动？输出中是否仍能读出原假设文本？快照缺席若干槽时，输入记录是否仍然成立？

### 触发与采集的相邻记录

适配器作者会碰到这两条相邻类型。它们不是模型绑定。

触发的输入可以是：键盘事件的一个子集；采集给出的静音一类信号；识别流给出的「分句已定稿」；宿主字段的失焦信号。这些信号都可以缺席。输出只有对某一会话的打开或关闭。被取走的事件不进入键盘组合。未被取走的事件原样进入键盘链，包括自有预编辑区间仍然存在的时候。触发不读取键盘组合状态。关闭信号不是提交文本。

开闭条件用按住、切换、静音还是定稿，007 缺口 8 与 008 §5.4 记为未知。若干宿主不把普通键的松开经输入法键盘事件送回，因此「以松开为关闭」不能只靠这条事件路径。条件未选，检测路径也未选。端口不把某一种手势写成参数默认值。

采集的输出是带显式格式的有序帧，或无帧并结束。使用权不成立时，输出为结束且不产生帧，不把「没有使用权」报成一段静音识别成功。更换帧格式不要求更换识别流的实现。识别流不打开麦克风。样本内部见过的采样数值不是本记录的不变量（007 缺口 6，009 §3.4，012 §3）。

## 关键实现决定

每条都是候选决定。追溯指 007 至 011 的节。异议栏说明是吸收进本参照，还是把仍未知的部分改记到 012。

### 决定 1：接口是九条原语的组合，不设总函数

候选决定：调用方看见的是会话上的九个端口与三份记录，不是一次「优化(采样) → 提交文本」。同一次进程内可以顺序调用这些端口。组合方式不另命名，不另设总控模块。

追溯：007 §2.2 焊法 A，007 §2.3，007 §4。008 §1.1 拒绝把四条收成一个语音态。

异议：五条异议都没有要求恢复总函数。012 未为此另开缺口。

### 决定 2：收束已请求与会话关闭是两位

候选决定：触发给出关闭时，会话仍开放且允许交付，字段不动。发出关闭信号的一方不获得写字段的权利。能写字段的时刻是会话仍允许交付的时候。关闭不回滚已提交文本，关闭之后也不补一笔清预编辑。失焦不是会话标识；触发不消费它，会话就不因为失焦这一件事关闭。字段标识偏离快照只把交付许可改为拒绝，不销毁假设，不把写入改道到新字段，也不在旧字段上补清理。

追溯：007 原语 1、原语 2；008 §1.2 舍弃乙、舍弃丙、舍弃辛，008 §3.4。

异议：无一条异议推翻这两位的分开。008#transaction 推翻的是「提交成功随即关闭」，不是「触发关闭不等于会话关闭」。见决定 5。

### 决定 3：未取走的键盘事件进入键盘链，不设预编辑闸门

候选决定：不取走的事件，不论当前有没有语音自有预编辑区间，都原样进入键盘链。事件内容不改。键盘链内部不增加语音分支，语音文本不编码成按键，触发不先跑一遍键盘链来区分这枚键会不会改预编辑。取走仍只用于开闭，且不写字段。

自有区间还在时字段会变成什么，本决定不预测。语音事务此后若对不上自己登记的范围，整笔拒绝。008 §4 反论三把「键盘链已被进入」追加为拒绝原因；该原因不是原语 1 的原文，本参照不写入状态机。008 §5.9 问的是出字之前的未取走键是否表示这轮语音应停止写字段，仍然未知，012 没有把这一问另开成缺口。

追溯：007 原语 2 的不变量「未被取走的键盘事件原样进入键盘组合，其组合状态不被触发读取」；007 焊法 E；007 原语 8。008 §3.5 的取走 / 不取走两分保留；同节「停在键盘链之外」不保留。008 §1.2 舍弃己、舍弃庚。008 §6.2 的直线键盘链只作为距离。

异议 008#coexistence：吸收。被点名的那段是「若有自有预编辑区间，未取走的事件停在键盘链之外，直到语音事务自己结束该区间」。那段闸门不进入会话状态机，也不进入共存约束。012 §1 改记的是另一件仍未知的事：事件进入键盘链之后，预编辑与提交各变成什么，以及语音交付还能不能对上原来的范围。012 写明观察不用来增加「先停在键盘链之外」的条件。本参照按该写法留下未知，不把闸门换一个名字再写回来。

### 决定 4：交付许可的基数沿用原语 1，不沿用一次替换的调用形状

候选决定：同一字段上可以有多枚会话同时处于允许交付。它们仍然不得把结果写进彼此的宿主范围。新的打开不因为旧会话仍允许交付而自己变成拒绝，旧会话也不因新的打开而被关闭。范围在宿主上无法对应到本会话有权替换的那一段时，这一条意图拒绝。

追溯：007 原语 1「标识不同的结果不写进彼此的宿主范围」。008 §3.4 自己写明原语 1 并不禁止两枚会话同时允许交付。008 §6 声明与 Squirrel 的对照是距离，不是设计。

异议 008#cardinality：吸收。不采用 008 §3.4 的候选迁移「该字段上已有一枚允许交付的开放会话时，新的打开不获得允许交付」，也不采用 008 §4 的倾向「同一字段标识上至多一枚会话处于允许交付」。008 §4 反论四已承认这不是对宿主能力的测量。012 没有把「一字段一枚」改记成缺口条目。仍未知的是 008 §5.10：同一宿主字段能否同时持有两段互不覆盖的预编辑。本参照不把这个未知收成打开时的拒绝。

### 决定 5：事务不把「至多一笔成功提交」收成不变量

候选决定：事务检查是接口一节的七项。同一会话可以先后成功应用多笔提交意图。提交成功不把寿命迁到已关闭，也不宣布这笔是最后一笔交付。呈现序列甲与序列乙都合法。事务不替呈现选择。交付在改写结果未到时不自己造优化文本；它也不因此拒绝「字符串就是已有假设原文」的那一笔提交。

关闭行只保留：收束已请求，呈现不再持有未发出的意图，且自有区间为无。序列甲在改写未到时仍持有待发提交，寿命保持开放。序列乙在替换用的第二笔尚未发出时同样保持开放。不引入钟点。

追溯：007 原语 7「先一直预编辑、到改写结束再提交一次，是一种配对，不是本原语的不变量」；007 §4；007 缺口 4「先提交再由改写替换同样满足原语 7」。008 §3.3 第 8 项里「交付不在改写未到时自己造优化文本」仍然保留。008 §1.3 写过「事务对两种意图序列都成立」，但同文 §3.3 第 6 项与 §3.4「提交事务成功然后进入已关闭」把其中一种焊进了检查。本决定取 §1.3 的前一句，不取第 6 项。

异议 008#transaction：吸收。不采用「应用提交之后已应用提交变为是，这笔是该会话最后一笔成功的交付」，也不采用「提交事务成功之后会话进入已关闭」作为唯一迁移。008 自己举的「先提交假设原文，改写结果到达后不再写」不是「再由改写替换」；序列乙保留后者。012 §2 改记两件宿主事实：收束之后、下一次写入之前，预编辑是否仍在字段上；对同一范围连续两次提交且第二次字符串不同时，文档历史上留下几段。未观察到之前，两种序列都成立。

### 决定 6：本地模型适配器的对外类型是原语 4 或原语 5

候选决定：调用方实现的本地适配器，输入输出只用识别流记录或改写流记录。快照用上下文一节的五个槽，不使用官方进程内的两层槽名。每条假设都带修订目标，不只带「部分或定稿」。格式写在帧上。豆包离线模型的绑定实例在没有进程外可调用契约时为空角色。内部路径、槽名、结果键留在观察里，不进入构造参数。

追溯：007 原语 4、原语 5、原语 9，007 缺口 1 与缺口 6。009 §2 对应到「帧与快照进、假设出」为止，并写明执行点在进程内。009 §4 的三送一收是该文自己的候选倾向，不是原语 4 的类型。009 §5 第 1 点与第 5 点：采样数值与修订粒度未知。

异议 009#adapter：吸收。不把「布局路径、样本 3.3 节的两层内部键、16-bit PCM 块，收回物只有文本加部分或定稿」交给调用方。012 §3 改记：这件制品还没有一份等于原语 4 的可调用契约；不需要再用进程内槽名、布局路径或「部分 / 定稿」来补；没有不依赖容器内部材料的入口时角色空着。本参照不打开容器来填这个空位。

### 决定 7：云端适配器不把点名接口换成另一套产品

候选决定：云端适配器的调用方类型只有改写流记录，以及在契约证明吃帧时的识别流记录。角色配对保持可换。豆包输入法云端大模型接口的实例现在是空角色。不把公开流式识别的音频请求、公开对话的消息数组，或样本整理路由的对象字段，写成这个端口的唯一形状。一份快照同时交给两个流；各适配器自己的装填不是快照类型。

追溯：007 焊法 B，原语 5，原语 6，原语 9，007 缺口 2 与缺口 3。010 §1.2 焊法 1 至焊法 6 里，本决定保留的是：不把私有长连接收成识别流的实现，不把样本决策枚举收成改写流的类型，不把识别请求里的语义顺滑当成改写流，不用一把凭证打两家。010 §4 把两套公开契约写成绑定目标，这一步不保留。011 §3.1 的快照形状保留为上下文端口；011 §3.4 写明优化请求的键名未知，且那是整理路由一侧的投影，不保留为端口。

异议 010#binding：吸收。不采用「用户点名的云端制品在这里拆成两面」，也不采用「输入法自己的长连接与整理路由不是绑定目标」这句话所转向的那两套公开产品。点名制品仍然是绑定要等的那一件；等不到可调用契约时角色空着，而不是改等另一件。012 §4 改记：010 与 011 没有交出同一份绑定；公开的两套接口与整理路由都不是已经核对过的点名契约；不提取令牌，不复刻签名，不把调用方进程换成官方输入法进程。其余原语的输入输出不因这个空位而改。

### 决定 8：上下文是一份快照，投影不升成端口

候选决定：会话打开时只读汇集一次，五个槽，缺席不是空字符串。修正对与热词在进入快照前已由各自来源挑选并消解，快照不带计数、时间戳和密文。识别假设不写进记忆。改写结果不写回快照，也不写回来源。本地内部槽位与云端报文都是适配器私有投影；两侧契约都不成立时，投影没有可核对的写入，快照类型仍然成立。

追溯：007 原语 6，007 焊法 D，007 缺口 5。011 §1.1 至 §1.3，011 §3.1，011 §3.2，011 §4。011 §3.3 与 §3.4 的投影表只作为「观察到的落点或逻辑草稿」被决定 6、决定 7 挡在端口之外。011 §5 第 10、11 点与 012 §3、§4 一致：官方进程之外能否接受那些投影，未知。

异议：009#adapter 与 010#binding 都涉及「把某一侧的内部字段当成对外契约」。决定 8 用同一道边界吸收这两条里和快照有关的部分：快照不被某一个模型私有，也不被某一条路由私有。012 没有单独为五个槽再开缺口；与投影能否落地相关的未知已经在 012 §3 与 §4。

### 决定 9：交付只消费意图，拒绝时字段逐字不动

候选决定：交付的输入是一条四字段意图、会话的交付许可、宿主当前是否接受写入。通过检查则整笔应用，任一检查失败则宿主字段与应用前逐字相同，包括不写入「临时先上屏」。更换识别或改写的绑定，不改变这组输入。键盘组合不读取意图。会话判定成拒绝时，识别可以继续产出假设，假设停在会话里。

追溯：007 原语 7、原语 8；008 §1.3、§3.2、§3.3。008 §6.3：把语音字符串送进现行键盘 `show` / `commit` 会让文本经过键盘预编辑缓存，那是缺口，不是通道。

异议：008#coexistence 与 008#transaction 已在决定 3、决定 5 吸收。决定 9 不把那两处焊法带回交付。012 §1 与 §2 仍约束本决定的边界：范围对不上就拒绝，但「对不上之后字段里已经是什么」以及「第二笔提交在文档历史上留下几段」都还未知，交付不为这两件未知增加新的检查项。

### 决定 10：点名制品的空角色不改其余端口

候选决定：两枚点名绑定的实例在契约未知时都是空角色。会话、触发、采集、呈现、交付与快照仍按本节的记录核对。核对用的识别替身不读取真实权重，核对用的改写是恒等。替身不打开容器，不连接私有主机，不装成官方输入法进程。空角色不是失败类型，快照空缺席也不是失败类型。

追溯：007 原语 9 的不变量与核对句；007 缺口 1、缺口 2。009 §4 反论：把路径和 PCM 写成不能运行的说明书，是因为契约未知时角色空着。010 §4：私有主机上的连接与决策字段没有被另一套凭证盖住。012 §3、§4 写明现在不需要用进程内材料或公开替代品来补。

异议：009#adapter 与 010#binding 的「接口因此不通用」由本决定收口。通用性来自端口类型保持原语 4、原语 5、原语 6，不来自把某一次厂商字段写成唯一调用方，也不来自把空角色填成另一家产品。

## 仍然未知，且本参照不补

下列各项 012 已经记下。这里只列与端口有关的那几条，避免把未知写成另一种倾向。

1. 预编辑已经在字段上时，一枚普通键进入键盘链之后，预编辑文本与提交文本各变成什么。012 §1。决定 3 不为此加闸门。
2. 先提交再由改写替换时，文档历史上留下几次提交；收束之后预编辑是否还留在字段上。012 §2。决定 5 不为此恢复「至多一笔」。
3. 豆包输入法离线模型在官方进程之外，有没有一份输入为帧、快照、会话标识，输出为带修订目标的假设的可调用契约。012 §3。决定 6 让角色空着。
4. 豆包输入法云端大模型接口在官方进程之外的请求形状，以及它接受帧、定稿文本，还是两者都接受。012 §4。决定 7 让角色空着，且不改用 010 的两套公开产品。

008 §5 里与状态机相邻、012 未再单列的未知，仍然有效，并且没有被收成新的迁移：字段标识的平台值；失焦是否等于字段偏离；交付时能否读回宿主预编辑范围；触发的具体开闭条件；改写一直不到达时有没有会话以外的关闭事实；同一字段能否同时持有两段预编辑。011 §5 里分隔字符、各长度上限、云端真实键名、输入框角色的读取接口，同样不在本参照里补一个数或补一个键。
